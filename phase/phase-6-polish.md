# Phase 6 — Real Usage & Polish

## Objective

Stop building new features.

Use FitFlow during real training.

The goal is to discover actual friction.

---

# Usage Period

Use the application consistently for approximately 2–4 weeks.

---

# Observe

Record:

## Workout friction

Examples:

* Too many taps
* Difficult set input
* Previous performance hard to find
* Exercise selection slow

## Nutrition friction

Examples:

* Meal logging too slow
* Macro input inconvenient

## Progress friction

Examples:

* Important information missing
* Too many charts
* Trends unclear

## Planning friction

Examples:

* Weekly plan doesn't match reality
* Availability changes frequently
* Recovery adjustments are too aggressive

---

# Product Rule

Only fix problems observed through actual use.

Do not add features simply because they sound interesting.

---

# Possible Improvements

Only if validated:

* Better mobile layout
* Faster set logging
* Quick-add nutrition
* Copy previous workout
* Keyboard shortcuts
* PWA
* Offline improvements

---

# Acceptance Criteria

After real usage:

1. Workout logging feels fast.
2. Previous performance is easy to access.
3. Progress is understandable.
4. Nutrition logging is tolerable.
5. Weekly planning is useful.
6. No unnecessary feature creates friction.

At this point the MVP is considered complete.

---

# Important

Do NOT start Phase 7 automatically.

Future features must be evaluated based on real usage.
